## 2026-08-11 — FR-6 removed

**Decision:** FR-6 (CouchDB `/_users/` URL encoding / plus-sign username support) removed from v4.2 scope.

**Reason:** The underlying `HtmlEncode` → `Uri.EscapeDataString` fix is technically correct but there is no active break case. The motivating scenario — Gmail `+` addressing for cheap SAMS test accounts — is moot because SAMS does not accept email addresses containing `+`. Test account coverage will be addressed via the FR-8 password-auth tenant (most role testing) and a small fixed set of pre-created named SAMS accounts.

**Revisit condition:** If a future scenario surfaces a real break due to special characters in `/_users/` paths, re-evaluate in the next release cycle.

Nick added a new major feature: unified server-side address geocoding (TAMU refactor). Three design decisions confirmed during Discovery:

| Decision | Choice | Rationale |
|---|---|---|
| CVS handling | **Server-side** — endpoint calls TAMU + CVS atomically | Consistent with atomic save goal; no partial state on network failure |
| Post-geocode client behavior | **Reload in edit mode** | Simpler, always correct; avoids JS field-update logic for 15 fields |
| Busy modal | **Reuse existing modal pattern** | No new component; consistent with site conventions |

**Divergence from existing Epic 30 design:**
- Epic 30 Story 30.4 AC-3 says CVS stays client-side after geocode response → **superseded by server-side decision above**
- Epic 30 Story 30.3 / 30.4 design returns `GeocodeResult` JSON for JS to update fields → **superseded by reload decision**
- Epic 30 does not specify a busy modal → **now required**

Epic 30 story-level amendments will be needed when `bmad-create-epics-and-stories` runs for v4.2.
